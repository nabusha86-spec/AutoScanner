# AutoScanner Trader

Стартовый Android-проект на Kotlin и Jetpack Compose для AutoScanner Trader.

## Текущее состояние

- Интерфейс приложения локализован на русский язык.
- На главном экране представлены ручной режим и режим автоматической торговли.
- Ручной режим выполняет захват и анализ только для рекомендаций; перед одиночным кадром единственное окно панели синхронно отсоединяется от `WindowManager`, а захват вооружается после трёх кадров отрисовки и принимает только изображения с более поздней временной меткой.
- «Запись» захватывает одну 15-секундную последовательность с интервалом 500 мс; окно панели остаётся отсоединённым от `WindowManager` на протяжении всей серии и до ответа анализа.
- Автоматический режим анализирует последовательность кадров в течение 15 секунд и продолжает циклы до остановки или критической ошибки. Существующее окно панели возвращается с результатом между циклами; повторные команды во время захвата или анализа игнорируются.
- Автоматический режим перед возможной попыткой нажатия анализирует 15-секундную последовательность; `TradingExecutionManager` допускает только одну попытку на уникальную команду. Accessibility разрешено получать события только от Chrome; перед чтением дерева проверяется только адресная строка `com.android.chrome:id/url_bar`, и полный экран читается только на HTTPS-хосте `pocketoption.com` или его поддомене. На иных сайтах, в других браузерах и приложениях чтение и нажатия блокируются. Нажатие также требует подтверждения пары, цены, суммы, выбранной экспирации и по одной активной кнопке BUY и SELL; координатные нажатия не используются.
- Пользователь сам включает службу AutoScanner в настройках Accessibility, открывает Pocket Option и выбирает счёт. Приложение не выполняет вход, не использует API и не меняет счёт, сумму или экспирацию.
- После нажатия интерфейс проверяется на явное подтверждение; результат сделки не считается подтверждённым. При неясном результате автоматический цикл останавливается и блокирует повторные сделки до разрешения ситуации. Сервис не отслеживает исход сделки и не может гарантировать, что платформа приняла действие.
- Реализованы и unit-тестируются правила суммы, мартингейла, последовательного счёта проигрышей, аварийной блокировки и ограничения домена Accessibility. Они не подключены к фактическому источнику результатов сделок Pocket Option.
- Неопределённый результат блокирует повторный автоматический запуск. Официальный источник исхода сделки в приложении отсутствует.
- Захват запускается только после системного подтверждения MediaProjection и работает в службе переднего плана типа `mediaProjection`.
- Для плавающей панели отдельно запрашивается стандартное системное разрешение «Поверх других приложений». Панель перемещается за заголовок, сворачивается в пузырёк и остаётся доступной поверх других окон, пока жива сессия захвата.
- Скриншот получает один актуальный кадр через уже активный `ImageReader`; он не включает непрерывную запись и не запрашивает повторное разрешение для действующей сессии. Кадр сохраняется в закрытом каталоге приложения и сразу проходит OCR/OpenCV-анализ.
- «Запись» и автоматический режим используют одну активную сессию MediaProjection и тот же `VirtualDisplay`; токен MediaProjection повторно не используется.
- Pocket Option не подключается по API, и приложению не передаются учётные данные. Для исполнения Accessibility дополнительно проверяет домен в адресной строке Chrome и видимое подтверждение бренда в дереве интерфейса; если браузер не предоставляет адресную строку или доступные элементы, попытка безопасно блокируется. Аналитика может обработать кадр в ручном режиме, но это не разрешает исполнение.
- Каждый сохранённый кадр последовательно проходит OCR, оценку качества, поиск цветных свечных компонентов и проверку торговых кнопок; сводка и покадровые данные сохраняются в `analysis.json` рядом с JPEG.
- OCR работает локально на Tesseract4Android 4.9.0 (Tesseract 5.5.1 LSTM) с офлайн-моделями `eng` и `rus` формата 4.0.0 из `tessdata_fast`; после установки сеть не требуется. Размер включённых моделей — около 7,7 МиБ. OpenCV 4.10.0 используется для эвристического анализа пикселей.
- Распознавание является консервативной базовой эвристикой: кнопка считается подтверждённой только при согласованном цвете и OCR-тексте; свечи ищутся как узкие красные/зелёные компоненты внутри предполагаемой области графика. Без достаточных признаков поля остаются «НЕ ОПРЕДЕЛЕНО». Это не подтверждает, что открыт именно Pocket Option.
- Время экспирации выбирается только из доступных интервалов 15, 30, 60, 120 или 180 секунд; при слабой согласованности используется минимальная экспирация. Распознавание пары включает AED/CNY OTC. Точность свечей, торговых кнопок и элементов интерфейса требует проверки на реальных кадрах разных устройств и тем оформления.
- История сохраняет прогнозы, но не подтверждённые результаты сделок. Точность распознавания остаётся эвристической; для проверки качества нужны реальные кадры с разных устройств и тем оформления.
- Остановка службы/задачи и закрытие приложения удаляют overlay и освобождают ресурсы. Ошибка отдельного кадра или анализа восстанавливает панель с сообщением; отзыв MediaProjection освобождает ресурсы захвата и оставляет доступное overlay для отображения ошибки. После остановленной сессии Android требует заново подтвердить разрешение захвата.
- Проверка реального времени захвата, Accessibility-дерева Pocket Option, фактического нажатия, принятия действия платформой, overlay-разрешения, отзыва MediaProjection и поведения службы на Android 14+ требует физического Android-устройства. Unit-тесты проверяют блокировку параллельных циклов и повторного исполнения одной команды; системные службы ими не моделируются.

OpenCV и модели OCR включены в APK: OpenCV содержит нативные библиотеки для Android ABI, а языковые данные занимают около 7,7 МиБ до упаковки. Размер итогового APK зависит от упаковки ABI и сжатия.

Для захвата необходимо подтвердить системный запрос на демонстрацию экрана и разрешить отображение поверх других приложений. На Android 14 и новее захват выполняется отдельной службой переднего плана типа `mediaProjection`; системные ограничения соблюдаются.

## Сборка локально

Требуются JDK 17, Android SDK Platform 35, Android SDK Build Tools 35.0.0 и доступ к сети для первой загрузки Gradle и зависимостей.

Откройте проект в Android Studio и запустите конфигурацию `app`, либо выполните из корня:

```shell
./gradlew :app:dependencies --configuration debugCompileClasspath
./gradlew :app:testDebugUnitTest :app:lintDebug
./gradlew :app:assembleDebug
```

Готовый debug APK создаётся по пути `app/build/outputs/apk/debug/app-debug.apk`.

Для установки на подключённое устройство с настроенным Android SDK:

```shell
./gradlew :app:installDebug
```

## Автоматическая сборка в GitHub Actions

Workflow `Android Build` находится в `.github/workflows/android-build.yml`. Он запускается при каждом push в `main`, при создании Pull Request и вручную через вкладку **Actions** (событие `workflow_dispatch`).

Workflow использует JDK 17 и существующий Gradle Wrapper, устанавливает Android SDK Platform 35 и Build Tools 35.0.0, проверяет зависимости, собирает debug APK и проверяет, что файл создан. Затем APK публикуется как downloadable artifact с именем `autoscanner-trader-debug-apk` и хранится 14 дней.

Debug artifact предназначен только для разработки и не должен использоваться как релизный APK. Подписанный недебажный APK собирается при push тега `v*` или ручном запуске workflow. Используйте постоянный отдельный Release keystore, не Android Debug Keystore; храните как минимум одну зашифрованную резервную копию вне Git и отдельно сохраните пароль. Настройте следующие GitHub Actions secrets репозитория:

- `ANDROID_RELEASE_KEYSTORE_BASE64` — keystore в кодировке Base64.
- `ANDROID_RELEASE_STORE_PASSWORD` — пароль keystore.
- `ANDROID_RELEASE_KEY_ALIAS` — alias ключа подписи.
- `ANDROID_RELEASE_KEY_PASSWORD` — пароль ключа.

Настройте GitHub Actions variable `ANDROID_RELEASE_CERT_SHA256` с SHA-256 fingerprint сертификата в шестнадцатеричном виде (двоеточия допускаются). Release job завершится ошибкой, если какого-либо секрета или переменной нет, APK допускает отладку, подписан стандартным Android Debug-ключом, его сертификат не совпадает с указанным fingerprint или проверка APK не проходит. Для релиза используйте отдельный постоянный keystore; его потребуется сохранить и резервировать для подписи всех будущих обновлений. APK загружается как artifact `autoscanner-trader-release-apk`; tag-сборка также публикуется как GitHub Release.

Secrets можно настроить через `gh secret set`, передавая файлы через stdin, чтобы не выводить значения в терминал. Не вставляйте приватный ключ или пароли в исходный код, workflow, issues или обычные логи. Не меняйте Release keystore для обновлений уже опубликованного приложения.

Чтобы скачать APK:

1. Откройте вкладку **Actions** репозитория и выберите успешный запуск **Android Build**.
2. На странице запуска найдите раздел **Artifacts**.
3. Скачайте `autoscanner-trader-debug-apk` — ZIP-архив содержит `app-debug.apk`.

Для ручного запуска откройте **Actions → Android Build → Run workflow** и выберите ветку. Также запустится сборка release APK, для которой нужны secrets подписи; результат доступен отдельно как `autoscanner-trader-release-apk`.
