# AutoScanner Trader

Стартовый Android-проект на Kotlin и Jetpack Compose для AutoScanner Trader.

## Текущее состояние

- Интерфейс приложения локализован на русский язык; `applicationId` остаётся `com.autoscanner.trader`.
- Приложение не содержит Accessibility Service, не читает дерево интерфейса других приложений и не выполняет нажатий BUY/SELL.
- Захват запускается только стандартным системным подтверждением MediaProjection и работает в службе переднего плана типа `mediaProjection`.
- Для плавающей панели отдельно запрашивается разрешение Android «Поверх других приложений». Панель перемещается, сворачивается в пузырёк и доступна поверх других окон в течение сессии захвата.
- Скриншот захватывает один кадр из активного `ImageReader`. Перед захватом панель удаляется из `WindowManager`, а после анализа возвращается с результатом.
- Запись захватывает 15-секундную последовательность кадров с интервалом 500 мс. Панель остаётся скрытой во время всей серии и анализа, затем возвращается с результатом.
- Кадры сохраняются в закрытом каталоге приложения и последовательно анализируются OCR/OpenCV. Направление определяется по свечам/движению, распознанным на фактических кадрах; при недостатке данных показывается отсутствие сигнала, случайное направление не подставляется.
- Результат включает объяснение и оценку уверенности анализа. Уверенность не является вероятностью выигрыша. Кнопка подтверждения только отмечает намерение пользователя выполнить действие самостоятельно; она не взаимодействует с Pocket Option.
- OCR работает локально на Tesseract4Android 4.9.0 с офлайн-моделями `eng` и `rus`; сетевые разрешения приложению не требуются. OpenCV 4.10.0 используется для анализа изображения.
- Эвристическое распознавание свечей и текста требует проверки на реальных кадрах, устройствах и темах оформления. Физическое устройство также необходимо для проверки поведения MediaProjection, overlay, системного отзыва разрешения и Android 14+.

OpenCV и модели OCR включены в APK: OpenCV содержит нативные библиотеки для Android ABI, а языковые данные занимают около 7,7 МиБ до упаковки. Размер итогового APK зависит от упаковки ABI и сжатия.

Для захвата необходимо подтвердить системный запрос на демонстрацию экрана и разрешить отображение поверх других приложений. На Android 14 и новее захват выполняется отдельной службой переднего плана типа `mediaProjection`; системные ограничения соблюдаются.

## Сборка локально

Требуются JDK 17, Android SDK Platform 35, Android SDK Build Tools 35.0.0 и доступ к сети для первой загрузки Gradle и зависимостей.

Откройте проект в Android Studio и запустите конфигурацию `app`, либо выполните из корня:

```shell
./gradlew :app:dependencies --configuration debugCompileClasspath
./gradlew :app:testDebugUnitTest :app:lintDebug
./gradlew :app:assembleDebug
```

Готовый debug APK создаётся по пути `app/build/outputs/apk/debug/app-debug.apk`.

Для установки на подключённое устройство с настроенным Android SDK:

```shell
./gradlew :app:installDebug
```

## Автоматическая сборка в GitHub Actions

Workflow `Android Build` находится в `.github/workflows/android-build.yml`. Он запускается при каждом push в `main`, при создании Pull Request и вручную через вкладку **Actions** (событие `workflow_dispatch`).

Workflow использует JDK 17 и существующий Gradle Wrapper, устанавливает Android SDK Platform 35 и Build Tools 35.0.0, проверяет зависимости, собирает debug APK и проверяет, что файл создан. Затем APK публикуется как downloadable artifact с именем `autoscanner-trader-debug-apk` и хранится 14 дней.

Debug artifact предназначен только для разработки и не должен использоваться как релизный APK. Подписанный недебажный APK собирается при push тега `v*` или ручном запуске workflow. Используйте постоянный отдельный Release keystore, не Android Debug Keystore; храните как минимум одну зашифрованную резервную копию вне Git и отдельно сохраните пароль. Настройте следующие GitHub Actions secrets репозитория:

- `ANDROID_RELEASE_KEYSTORE_BASE64` — keystore в кодировке Base64.
- `ANDROID_RELEASE_STORE_PASSWORD` — пароль keystore.
- `ANDROID_RELEASE_KEY_ALIAS` — alias ключа подписи.
- `ANDROID_RELEASE_KEY_PASSWORD` — пароль ключа.

Настройте GitHub Actions variable `ANDROID_RELEASE_CERT_SHA256` с SHA-256 fingerprint сертификата в шестнадцатеричном виде (двоеточия допускаются). Release job завершится ошибкой, если какого-либо секрета или переменной нет, APK допускает отладку, подписан стандартным Android Debug-ключом, его сертификат не совпадает с указанным fingerprint или проверка APK не проходит. Для релиза используйте отдельный постоянный keystore; его потребуется сохранить и резервировать для подписи всех будущих обновлений. APK загружается как artifact `autoscanner-trader-release-apk`; tag-сборка также публикуется как GitHub Release.

Secrets можно настроить через `gh secret set`, передавая файлы через stdin, чтобы не выводить значения в терминал. Не вставляйте приватный ключ или пароли в исходный код, workflow, issues или обычные логи. Не меняйте Release keystore для обновлений уже опубликованного приложения.

Чтобы скачать APK:

1. Откройте вкладку **Actions** репозитория и выберите успешный запуск **Android Build**.
2. На странице запуска найдите раздел **Artifacts**.
3. Скачайте `autoscanner-trader-debug-apk` — ZIP-архив содержит `app-debug.apk`.

Для ручного запуска откройте **Actions → Android Build → Run workflow** и выберите ветку. Также запустится сборка release APK, для которой нужны secrets подписи; результат доступен отдельно как `autoscanner-trader-release-apk`.
